# Changelog

## Unreleased
- **README and docs split**: the README now focuses on the theme, preview, supported software and quick install, with an English mirror in `README_EN.md`. Design constraints, full installation, development and publishing moved into `docs/`, generated by `pnpm build:docs` from `showcase/docs/` and covered by the release drift check.
- **Showcase split from the theme**: every presentation source now lives under `showcase/` (shared specimen rendering, the product site, the palette reference and the README screenshot pipeline), with separate `pnpm build:site`, `pnpm build:docs` and `pnpm capture:preview` entries. `src/` only contains the palette and the supported software targets, while `site/` and `docs/` hold build outputs. The gallery is rendered in memory and screenshotted directly, so `preview/index.html` and `preview/gallery.html` are no longer generated.

## 0.5.0
- **DeepSeek Harness (DSH)**: a new target generates four installable theme plugins under `dist/dsh/`. The menu edition packs all six flavors into one plugin with a **Settings → General** switcher, while `inkstone-dsh-ink` / `-ink-dimmed` / `-sea` override DSH's built-in light/dark palettes for people who never want to pick a theme. Install from source with `pnpm install:dsh`; releases attach the matching `.tgz` files. Post-build checks run each browser bundle in a sandbox and assert it covers the frozen DSH 0.2.1 token ladder, so a token change fails the build instead of shipping a partial theme.
- **Zed extension version**: `dist/zed/extension.toml` now takes its version from the root `package.json` through `src/version.ts`, the same helper the checks use, so the manifest can no longer drift from the built themes.
- **Release drift check covers every committed output**: `src/outputs.ts` owns one list of generated files, and `pnpm release:check` verifies the site pages, `docs/palette.md` and `site/favicon.png` alongside the VS Code themes instead of trusting whatever `dist/` happens to hold.
- **Stricter release inputs**: every release script accepts `--flag=value`, rejects unknown flags instead of ignoring them, and refuses to tag when the changelog has no section for the version being released.
- **Palette registry**: flavors are derived from their families and the registry asserts itself, and the VS Code `contributes.themes` list is validated against the palette, so a renamed or missing flavor fails the audit.
- **Shared target plumbing**: `GeneratedFile` lives in `src/targets/types.ts`, ANSI key spelling lives in `src/targets/ansi.ts` (with tests), and the Kaku Lua and TOML schemes serialize from one terminal model.

## 0.3.5
- **玄墨关键字离开粉红侧**: `keyword` / `storage` / `deleted` move from 海棠红 · 降彩 (`#da5761`, H≈18.6) to 鱼鳃红 · 降彩 (`#d8574a`, H≈28.5), keeping the same lightness and chroma. 玄墨 Dimmed moves from 山黎豆红 (`#c27c88`) to 桂红 · 降彩 (`#c57f73`), a muted brick instead of dusty rose.
- **Red leaves the interaction layer**: selection highlight, range highlight, bracket match, overview ruler and chat slash commands now use each flavor's action blue instead of the keyword red; the bracket color cycle ends on red instead of starting with it. Annotation red is left to keywords, errors and deletions.
- **One warm family in 玄墨**: numbers / booleans / constants move from 杏黄 to 土黄, and types move to 萝兰紫, so the syntax layer no longer runs 杏黄 and 土黄 at the same time. 杏黄 stays reserved for warnings, and search highlights inherit the calmer 土黄.

## 0.3.3
- **Cursor chrome outlines**: `contrastActiveBorder` is transparent. Cursor paints that token as a 1px outline around editor tabs, activity-bar items and auxiliary actions such as New Agent; VS Code and VSCodium only use it in high contrast, where the dark default is already null.

## 0.3.2
- **Palette comfort pass**: the audit now checks contrast bands and OKLCH chroma budgets, not just minimum ratios. Body text moves from 13.5–14.3:1 to ≈11.5:1, and syntax colors above 9:1 are brought back into range.
- **Cinnabar, softened**: the red family keeps its traditional hue and lightness but drops to C≈0.165 (errors 0.18), so 海棠红 / 银朱 / 鹤顶红 / 尖晶玉红 read as pigment instead of neon. `soften()` records the source color for the docs.
- **Cursor decoupled from keywords**: a new `text.cursor` token uses each flavor's cool interaction color (羽扇豆蓝 / 涧石蓝 / 玉鈫蓝) instead of the annotation red.
- **Dimmed, reframed**: the dark canvas deepens instead of lifting into grey, the light canvas keeps its ink dark, and pigments retain ~75% chroma. Dimmed body text now clears 10.5:1 and punctuation is readable.
- New **OpenCode** target: all six flavors are generated as OpenCode V2 themes (`base` + mode hue scales) and installed with `pnpm install:opencode`.
- The OpenCode build maps the same semantic palette to text, surfaces, syntax, diff, Markdown, feedback fills and nine-step hue scales; `accent` is cinnabar and `interactive` is 晴山蓝.
- Post-build checks now verify OpenCode JSON, token references and text/fill contrast, alongside the VS Code, Ghostty and Kaku checks.
- GitHub Releases now ship per-target archives, a machine-readable `manifest.json` and `SHA256SUMS`; pushing a `v*` tag builds and publishes them automatically.
